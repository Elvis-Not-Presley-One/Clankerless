# Commitments Guideline

---

| Type         | Purpose                                      |
| ------------ | -------------------------------------------- |
| **feat**     | New feature                                  |
| **fix**      | Bug fix                                      |
| **docs**     | Documentation only                           |
| **refactor** | Code change that doesn't alter behavior      |
| **chore**    | Maintenance (deps, formatting, repo hygiene) |
| **ci**       | CI/CD and workflow changes                   |

Examples: `feat(dsp): add JP-8000 supersaw and N-voice unison engine`,
`fix(api): handle null patientId`, `ci: install pnpm via npm`,
`feat(api)!: rename /v1/messages to /v2/messages` (breaking change).
Subjects stay short (< 72 chars), imperative mood ("add", "fix", "remove").
